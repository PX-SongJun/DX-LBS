## 2. 목업·화면 연결표

U 번호는 설계 대상을 뜻합니다. 실제 페이지 수는 목업에서 정합니다.

| 화면 ID | 대상 | 기능 ID |
|---|---|---|
| U01 | 공통: 접근 진입·권한 없음 | F11·F16, 생성·출력 권한 |
| U02 | 어드민: 블록·자산·버전·발행 | F04·F08·F17·F19·F22-F24·F40 |
| U03 | 유저: 열람·목차·버전·자산 받기 | F11·F12·F14·F16 |
| U04 | 어드민: 템플릿 등록·변경 필드·갤러리 설정 | F31·F35 |
| U05 | 유저: 템플릿 갤러리·판형 | F26·F32 |
| U06 | 유저: 적용물 내용 변경·출력 | F27-F30·F37 |
| U07 | 유저: AI 이미지 생성·결과 선택·적용 | F30·F37 |
| U08 | 유저: 그래픽 생성·수정·결과 | F30·F38 |
| U09 | 어드민: 허용 대상·일부 발행 | F39 |

U02-U03을 먼저 전달하고, U05-U06을 제작 흐름으로 묶습니다. U04·U07-U09는 등록·생성·권한 방식 합의에 맞춰 전달합니다.

### 목업 전달 항목

- 화면 ID, 링크·버전, 전달 예정일
- 정상·빈 상태·처리 중·실패·권한 없음
- 진입·뒤로 이동·취소·완료·작성 중 이탈 동작
- 긴 제목·여러 블록·다른 크기의 이미지 등 실제 자료
- 합의한 조작 범위와 미결 질문
- 모의 처리 구간과 실제 연결 시점

블록 제거·복제·되돌리기·이미지 자르기는 구현 전에 범위를 확인합니다. 개발 중 모의 처리는 가능하며, 1차 완료 전 핵심 기능을 실제 연결합니다.

## 3. 개발 담당과 연결

| 영역 | 프론트엔드 | 백엔드·처리 |
|---|---|---|
| 접근·일부 발행 | 대상 지정·접근 안내 | 권한 확인·허용 데이터와 파일 제공 |
| 블록·자산 | 편집·업로드·저장 상태 | 저장·조회·파일 보관 |
| 버전·발행 | 발행 조작·목차·버전 표시 | 편집본·발행본 연결 |
| 템플릿 | 등록·갤러리·내용 변경 | 템플릿·브랜드 기준·입력 연결 |
| AI·그래픽 | 생성·수정·결과·재시도 | 생성 요청·결과 보관·실패 처리 |
| 출력 | 용도 선택·파일 받기 | 용도별 파일 생성·제공 |
| 배포·설치 | 환경별 화면 동작 확인 | 1차 내부 배포, 2차 독립 설치·자료 분리 |

프론트엔드·백엔드는 입력, 성공·실패 응답, 권한·파일 처리와 연결 시점을 합의합니다. 데이터 구조와 기술 구성은 개발자가 검토합니다. Next 계열·Python 기반 처리는 후보입니다.

UX 목업과 AI 시험은 송준님 한 사람의 일정으로 배치합니다. 기술 지원자는 가용 시간·전달 결과가 확인된 범위만 일정에 반영합니다.

### 출력 규격 확인

| 용도 | 결정할 항목 |
|---|---|
| 디지털 | 픽셀 크기·파일 형식·투명 배경 등 필요한 옵션 |
| 인쇄 | 실물 크기·해상도·형식·색상 처리·여백·재단선·글꼴 처리 |
| AI·그래픽 원본 | 단독 파일 제공·보관 범위, 템플릿 적용물과의 구분 |

인쇄소 확인·시험 인쇄의 필요 여부와 확인 담당을 정합니다. 실물 제작 대행은 포함하지 않습니다.

## 5. 검증과 변경 기록

각 WBS 세부 업무 종료 시 결과 링크·버전, 확인자, 수정 사항과 다음 작업 영향을 공유합니다. 수정이 필요하면 담당자와 재확인 시점을 정합니다.

| 종료 업무 | 확인할 결과 |
|---|---|
| UX 목업 | 화면·조작·상태와 개발 착수에 필요한 결정 |
| AI 시험 | 실제 결과·입력 조건·실패 사례와 제품 연결 방법 |
| 프론트엔드 | 실행 화면·상태와 실제·모의 연결 구간 |
| 백엔드 | 해당 처리의 성공·실패·권한 확인 결과 |
| 통합·배포 | 본문 6장의 시나리오와 실제 출력 파일 |

AI 시험 완료와 제품 연결 완료는 구분합니다. 변경 요청은 `관련 기능·화면·작업 / 변경 이유 / 필요한 결정 / 일정 영향`으로 기록합니다.

## 6. 독립 설치·인계

2차에는 다음 순서로 고객 설치본을 준비합니다.

1. 제공할 공통 원본 버전과 브랜드별 변경 범위를 정합니다.
2. 별도 환경을 만들고 브랜드 정보·접근 권한을 설정합니다.
3. 데이터·자산을 분리하고 가이드라인·템플릿을 등록합니다.
4. 열람·제작·생성·출력 흐름을 확인합니다.
5. 버전·변경 사항·알려진 제한과 사용·지원 방법을 인계합니다.

| 버전 | 관리 대상 |
|---|---|
| 공통 원본 | 내부에서 발전시키는 제품 기능 |
| 고객 설치본 | 고객에게 제공한 제품과 브랜드별 맞춤 변경 |
| 가이드라인 발행본 | 관리자가 발행한 브랜드 콘텐츠 |

공통 원본 변경은 고객 설치본에 자동 반영하지 않습니다. 업데이트 전 대상 버전·맞춤 기능 영향·적용 담당과 방법을 확인합니다.
